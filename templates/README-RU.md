# Входные файлы VoiceForge

Это шаблоны для текущего импортёра VoiceForge. Новые тесты и генерация при их подготовке не запускались.

Все названия Example.esp, FormID и имена FUZ в примерах вымышленные. Они показывают структуру файлов, а не реальные пути Skyrim. Перед генерацией замените их подтверждёнными данными вашего мода. Аудиоэталоны в комплект не входят.

## Что принимает программа

Один из двух вариантов:

1. Пара CSV: `lines.csv` с репликами и `paths.csv` с точными игровыми путями FUZ. Рекомендуется для выгрузки из модов и редактирования таблиц.
2. `jobs.json`: готовый список заданий. Удобнее для ручной подготовки небольшого набора или экспорта скриптом.

Дополнительно для новых Skyrim-клонов: `ref_candidates.json` и папка `refs` с оригинальными аудиоэталонами. Можно указать существующую библиотеку из прошлых проектов вместо создания новой. Если в интерфейсе выбран Fish library reference_id для голоса, его аудиоэталоны не требуются.

Не нужно подавать оба формата реплик одновременно. Сама программа пока не извлекает строки из ESP/ESM/ESL, BSA, DOCX, XLSX или TXT.

## Вариант 1. Два CSV

Скопируйте `lines.template.csv` в `lines.csv`, а `paths.template.csv` — в `paths.csv`. Первую строку с заголовками оставьте без переименования. `lines.example.csv` и `paths.example.csv` показывают заполненный вариант.

Кодировка — UTF-8 или UTF-8 с BOM. Рекомендуемый разделитель — запятая; импортёр также распознаёт точку с запятой и табуляцию. Текст с запятыми или переносами строк заключайте в двойные кавычки; внутреннюю двойную кавычку записывайте как две кавычки.

### lines.csv

Одна строка — один ответ INFO: комбинация `info_formid` и `response_number` должна быть уникальной.

| Столбец | Значение |
|---|---|
| `id` | Удобный идентификатор строки, например LINE_001. Для CSV импортёр создаёт собственный ID задания; этот столбец справочный. |
| `info_formid` | Ключ записи, например `000800:Example.esp`. Записывайте одинаково в обоих CSV: импортёр сопоставляет строки по нему, а не обращается к игре. |
| `response_number` | Номер ответа внутри INFO, целое число. Берите настоящий ResponseNumber записи, не номер строки таблицы. |
| `needs_voice` | Явно `yes` — озвучивать, `no` — исключить. Не оставляйте пустым. |
| `voice_text (stage directions removed)` | Точный текст для произнесения, без непроизносимых ремарок. Для `yes` не может быть пустым. |
| `subtitle_text (as in game unchanged)` | Необязательный справочный текст субтитров. Этот столбец программы не изменяет игру и не участвует в синтезе. |

Обязательная практическая часть шаблона: `info_formid`, `response_number`, `needs_voice`, `voice_text (stage directions removed)`. `id` и субтитры можно оставить для удобства. Другие справочные столбцы допустимы, но импортёр их не сохраняет как данные задания.

### paths.csv

Одна строка — один итоговый игровой путь.

| Столбец | Значение |
|---|---|
| `game_path (relative to Data)` | Точный путь `Sound/Voice/Plugin.esp/VoiceType/filename.fuz`, без `Data/`, буквы диска и начального слеша. |
| `info_formid` | Тот же ключ, что в lines.csv. |
| `response_number` | Тот же номер ответа. |
| `voice_type` | VoiceType из предпоследней папки пути; рекомендуются строчные буквы, например `maleguard`. |

Для одной реплики может быть несколько строк paths.csv: по одной на каждый подтверждённый VoiceType/файл. Все строки paths.csv должны находить соответствующую строку lines.csv. Строки lines.csv без путей сейчас не создают заданий: если путь неизвестен, отдельно включите их в отчёт о несопоставленных строках.

Импортёр объединяет одинаковый текст для одного VoiceType в одно задание и записывает результат во все его пути. Разные VoiceType получают отдельную генерацию. Один и тот же FUZ-путь нельзя назначать нескольким заданиям.

При импорте CSV поле «Префикс путей JSON» не используется. В примере получится два задания для двух голосов; путь строки LINE_002 будет исключён.

## Вариант 2. jobs.json

Скопируйте `jobs.example.json`, замените данные и сохраните как `jobs.json`. Верхний уровень — непустой JSON-массив, без комментариев и завершающих запятых.

Каждое задание содержит:

| Поле | Значение |
|---|---|
| `id` | Уникальный ID, 1–180 латинских букв, цифр, `_` или `-`. Не используйте кириллицу, пробелы или точки. |
| `vt` | VoiceType/ключ выбора голоса: латинские буквы, цифры, `_` или `-`. Используйте строчные буквы. |
| `text` | Непустой точный текст для синтеза. |
| `targets` | Непустой список относительных FUZ-путей для этого же голоса и текста. |

В примере пути уже полные относительно Data. Поэтому при импорте оставьте «Префикс путей JSON» пустым.

Старый формат с `targets: ["maleguard/filename.fuz"]` тоже поддержан: тогда укажите префикс `Sound/Voice/Example.esp` в окне импорта. Не добавляйте его повторно к уже полным путям.

Несколько targets в одном задании допустимы только для одного и того же синтезированного звука и липсинка. Если голоса или произносимые тексты различаются, создайте отдельные задания. Для пропуска строки просто не включайте её в jobs.json и укажите причину в отдельном отчёте.

Если текст или голос изменён, создайте новый ID/новый проект и не подключайте старый WAV как готовый результат новой реплики. Манифест уже созданного проекта редактировать вручную нельзя: у него проверяется контрольная сумма.

## Библиотека эталонов

Скопируйте `ref_candidates.example.json` в `ref_candidates.json`. Замените placeholder-транскрипты точными словами из реальных аудио. Рядом расположите:

```text
input/
  lines.csv
  paths.csv
  jobs.json                 # альтернатива двум CSV
  ref_candidates.json
  refs/
    maleguard/
      reference_01.wav
      reference_02.wav
    femalenord/
      reference_01.wav
```

Каждому vt должен соответствовать ключ в JSON, если вместо эталонов не выбран library reference_id. Поля эталона: `file` — имя файла относительно папки голоса, `text` — точная транскрипция этого файла. Поддерживается необязательное `source_voice_type`, задающее другую папку под `refs/`; используйте только при намеренном выборе другого источника и зафиксируйте замену в отчёте.

Для нового набора лучше несколько чистых реплик одного голоса без музыки и наложенной речи. Эталон должен соответствовать своему транскрипту. Нельзя заполнять транскрипт текстом новой реплики, если эталон произносит другие слова.

Вместо копирования библиотеки в каждый набор можно в интерфейсе указать существующий ref_candidates.json: программа ищет refs рядом с ним.

## Повторное использование WAV

Необязательная папка `wav_raw` содержит `<id>.wav` для соответствующего исходного jobs.json. Её можно подключить при JSON-импорте с явной отметкой использования готовых WAV. Сопоставление производится по ID; программа не распознаёт произнесённые слова для подтверждения совпадения текста.

При CSV-импорте переиспользование этой внешней папки отключено, поскольку CSV создаёт собственные ID заданий. Для ручного текста без существующего WAV оставьте поле пустым.

## Как писать вручную

Проще всего заполнить jobs.json. Напишите текст, укажите голос и реальные игровые пути. Чтобы услышать новую пробу, импортируйте проект, выберите задание в очереди и нажмите «Проба выделенных WAV».

Текущая версия требует targets даже для проб WAV. Отдельного режима «только текст и голос без Skyrim-пути» ещё нет. Вымышленный путь из примера пригоден для отдельного пробного проекта, но его FUZ нельзя считать готовой озвучкой существующего диалога.

Новый вручную написанный текст сам по себе не добавляет диалог в ESP. Если реплики ещё нет в игре, сначала нужны настоящие записи диалога и их точные пути. VoiceForge генерирует звук и липсинк, но не создаёт и не исправляет эти записи.

## Как получить файлы нейросетью

Передайте агенту с доступом к установленным модам файл `PROMPT-EXTRACT-RU.md` и укажите конкретные плагины и MO2-профиль. Он должен читать фактические данные, сохранять исходные моды и отдельно перечислять неопределённые сопоставления. Без доступа к данным мода нейросеть может заполнить структуру шаблона, но не подтвердить FormID, голос или имя FUZ.

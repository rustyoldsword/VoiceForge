# Задание агенту: подготовить входной набор VoiceForge из Skyrim-мода

Заполни параметры перед передачей агенту:

- MO2 instance: `<полный путь>`
- MO2 profile: `<имя профиля>`
- Target plugins: `<точные имена ESP/ESM/ESL>`
- Export directory: `<новая отдельная папка>`
- References: `<путь к существующему ref_candidates.json или запрос на подбор оригинальных эталонов>`
- Scope: `<все NPC-реплики / только перечисленные квесты или INFO / только отсутствующие файлы>`

Подготовь набор входных файлов для VoiceForge. Выполни извлечение фактических данных, а не заполняй неизвестные поля догадками. Не запускай Fish, генерацию аудио, сборку FUZ или тесты; нужно только извлечение и описание входных данных.

Сначала прочитай приложенный README-RU.md и шаблоны. Если работаешь в Codex/Claude с доступным houseCARL, используй его для чтения диалогов, активного load order и разрешённых игровых путей через выбранный MO2-профиль. Соблюдай применимые инструкции инструментов. Если доступа к MO2 или записям нет, явно сообщи это: не имитируй прочитанные записи.

Не изменяй исходные моды, плагины, BSA, modlist.txt, plugins.txt и loadorder.txt. Экспорт сохраняй в новую отдельную папку. Не читай и не выводи API-ключи, .env.local или другие секреты.

Результат:

1. `lines.csv`, UTF-8, заголовки:

```csv
id,info_formid,response_number,needs_voice,voice_text (stage directions removed),subtitle_text (as in game unchanged)
```

Одна строка на комбинацию INFO + настоящий ResponseNumber. Используй фактический текст нужной версии записи; зафиксируй, читаешь ли ты load-order winner или исходную версию плагина. Сохраняй ключ формы с определяющим плагином в согласованном формате `XXXXXX:Plugin.esp`, а не с переменным runtime-префиксом load order. Значение этого ключа должно точно совпадать в обоих CSV. VoiceForge не преобразует разные написания FormID в один ключ.

Субтитры сохрани без изменений. В поле синтеза убирай только явно непроизносимые ремарки, не переписывая содержание. Не считай любую фразу в скобках ремаркой автоматически. Сомнительные случаи вынеси в отчёт. Для явно безречевых ответов ставь needs_voice=no и объясняй исключение; междометия не удаляй молча.

2. `paths.csv`, UTF-8, заголовки:

```csv
game_path (relative to Data),info_formid,response_number,voice_type
```

Одна строка на точный путь `Sound/Voice/Plugin/VoiceType/filename.fuz`. Один ответ может иметь несколько путей для разных голосов. Определи нужные VoiceType по фактическим говорящим/условиям/алиасам и данным озвучки. Не назначай все голоса из папки всем репликам автоматически.

Для замены существующей озвучки используй точные пути loose/BSA/VFS, сопоставив каждый файл с INFO и номером ответа. Наличие файла в архиве само по себе не доказывает, что он соответствует нужной записи или выигрывает в активном профиле.

Для отсутствующих файлов получай имя из достоверного экспорта или поддерживаемого инструмента, умеющего правильно вычислять голосовые пути. Не выводи имя FUZ только из INFO EditorID, не угадывай усечение Quest/Topic EditorID, префиксы FormID или расположение папки плагина. Если точный путь подтвердить нельзя, оставь строку в отчёте несопоставленных реплик и не добавляй вымышленный путь в paths.csv.

3. `unmatched.csv` с полями `info_formid,response_number,reason,source`. Перечисли все реплики без подтверждённого пути, неоднозначные голоса, orphaned-файлы и конфликты сопоставлений. Не скрывай их ради полного счётчика.

4. `EXPORT-REPORT-RU.md`: источник и версия данных, профиль, список плагинов, способ получения путей, число INFO-ответов, число needs_voice=yes/no, число уникальных путей, число несопоставленных строк и все замены источников голоса. Укажи, что строки lines.csv без paths.csv не создают заданий в нынешнем VoiceForge.

5. При необходимости библиотека эталонов: `ref_candidates.json` и `refs/<vt>/*.wav`. Сначала попробуй использовать указанную существующую библиотеку. Если подбираешь новые эталоны, бери оригинальное аудио нужного голоса и подтверждённый текст именно этой записи. Не заменяй его библиотечным Fish-голосом или другим VoiceType без явного указания в отчёте. Не придумывай транскрипты. Если эталонов для голоса нет, перечисли его отдельно.

Формат ref_candidates.json:

```json
{
  "maleguard": [
    {"file": "reference_01.wav", "text": "Точные слова из reference_01.wav"}
  ]
}
```

Вариант `jobs.json` вместо двух CSV разрешён, если заранее известны точные пути. Его схема: массив объектов `{id, vt, text, targets}`. ID уникальны, ASCII буквы/цифры/`_`/`-`; vt — строчный ключ голоса; targets — непустой список полных путей относительно Data. Одно задание содержит только один голос и один текст. Одинаковые пары голос+текст можно объединять, сохраняя все подтверждённые targets. Не назначай один путь разным заданиям.

Не копируй вымышленные Example.esp/FormID/filename из шаблонов в реальный экспорт. В финальном ответе укажи папку экспорта, выбранный формат и оставшиеся неопределённости.
